# 小程序明确语音打断实时确认 Release 20260725-232632

## 发布目标

- 修复真机播放期间用户说出“等一下”“停一下”后，Agent 已检测到 barge-in 但仍等待
  VAD 端点和声纹任务结束，导致原回复继续播放的问题。
- 让统一 `UtteranceRouter` 已确认的明确控制语在流式 ASR interim 阶段启动当前 PCM 的
  声纹校验；确认可用后立即走既有 LiveKit 停止桥接，不再等整句 endpoint。

## 根因与修复

- 开启 TargetSpeakerFocus 时，播放期候选输入只能在 final transcript 后调用
  `_confirm_target_speaker_interrupt`。真机的 endpoint 延迟会使短控制语在回复接近结束后才
  生效，即使日志已经出现 `barge_in_detected` 和用户上行音频。
- 现在仅对已由 `UtteranceRouter` 识别为明确打断的、包含真实 PCM 的 interim 输入提前启动
  当前声纹校验；明确的 shadow guest / formal guest 仍被拒绝，普通 VAD 自动打断仍等待
  endpoint，避免将早期噪声或回声误判为主人。
- 被确认的控制语通过既有 `on_real_interrupt → session.interrupt` 唯一停止桥接，保持
  generation fence、已听文本、控制 ack 和小程序 `audio_reset` 的原有一致性。
