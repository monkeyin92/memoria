# 小程序受控双工与回声缓解 Release 20260726-111550

## 发布目标

- 修复真机 AI 首段卡顿、短暂播放后停止，以及外放回声导致“等一下”无法稳定打断的问题。
- 保持 H5 与既有 Cascade Agent 不变，只发布小程序客户端和独立媒体网关适配层。
- 为尚未通过设备级语音打断验收的真机提供本地优先“轻触打断”兜底。

## 根因与修复

- 生产时间线显示两次助手播放分别在约 0.84 秒和 0.90 秒出现自身回声候选插话；其中一次从候选到真正停止又耗时约 1.71 秒。豆包首 PCM 约 0.23 秒，不是主要瓶颈。
- 客户端原来每 20 ms 创建一个 source，遇到任一 sequence gap 会停止全部正在播放和已排程音频。现在按 80 ms 聚合；1–3 帧小缺口做有界静音补偿，大缺口或 generation barrier 才硬清。
- 下行协议新增可协商的 generation v2 头；权威 `speaking` 建立新代际 barrier，并阻止旧 source 复活。
- 网关新增小程序专属 WebRTC APM：已发送下行作为 reverse reference，16 kHz 上行清理后再发布；异常时旁路。generation reset 保留健康 APM 已学习的声学路径。
- 打断确认音 `memoria-ack` 使用独立临时轨并绑定当前 generation，不再被旧主轨 quarantine 一并丢弃。
- AI 讲话时显示“轻触打断”：先本地 5 ms 停播并隔离旧 generation，再复用现有 `stop-response`。客户端回传的 playout 事件仅用于日志关联，不具备业务控制权限。
