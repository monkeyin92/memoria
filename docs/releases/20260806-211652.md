# LiveKit 冷路径 Coturn 门禁修复 Release 20260806-211652

## 根因与修复

- 候选 `20260806-201007` 已完成制品验签和隔离 smoke，但 Control API 的 production
  校验无条件要求 `COTURN_URLS` 与 `COTURN_SHARED_SECRET`，阻断了当前尚未启用的
  `livekit + 0% StreamCore` 生产路径。
- 现在只有在 `MEDIA_RUNTIME_DEFAULT=streamcore`、
  `STREAMCORE_EXPERIMENT_PERCENT>0` 且 kill-switch 未开启时才要求 coturn。LiveKit-only
  会话可安全返回空 `ice_servers`；真实 StreamCore rollout 缺少 HTTPS WHIP、签名材料、SLO
  gate、coturn URL 或独立 coturn secret 时仍 fail closed。

## 发布范围与边界

- 仅修复 Control API 的 rollout 配置门禁及回归测试；不启用 media-runtime profile，生产继续
  使用 `python_authoritative + LiveKit`。
- `20260806-201007` 已回滚至 `20260802-142257`，H5 从未切换。本 release 复用其失败候选
  作为增量镜像构建与上传 basis，但所有 source/images/H5 provenance 均会重新绑定本 tag。
- 真正的 coturn relay、跨主机 WebRTC、设备播放 ACK、AEC、多实例 ownership、容量与 Chaos
  仍是外部门禁，不能由这次配置修复关闭。

## 发布前门禁

- `services/control_api/tests/test_session_api.py` 通过，新增 LiveKit 无 coturn 与 StreamCore
  启用仍要求 coturn 的对称回归。
- `uv run mypy services --strict` 通过 237 个 source files；H5、Go、其余 Python 门禁沿用
  `20260806-201007` 已验证结果。

本节在完成新的 source/images/H5 artifact 验签、隔离 smoke、runtime/H5 原子切换、provider
readiness 和公网验收后补录。任一门禁失败时保持或恢复到 `20260802-142257`。
