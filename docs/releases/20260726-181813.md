# 小程序“等下”语音打断热修 Release 20260726-181813

## 发布目标

- 修复小程序播放期用户说“等一下”时，FunASR 识别为口语短写“等下。”后被
  `UtteranceRouter` 判为普通聊天、因此无法停止 AI 播放的问题。
- 复用 `20260726-161236` 已有 AEC 声学 witness、播放 epoch、TargetSpeakerFocus 与
  单一 Router 控制面；不调整 voiced 阈值，不新增旁路关键词处理。

## 根因与修复

- 公网 WSS 失败会话 `60d48171-cf20-4487-9df4-ec9d72260d04` 证明 AEC 后声学证据已成立：
  通用 `0.012` 阈值下有 180 ms voiced，RMS 为 `0.09197`，witness 年龄为 1 ms；
  `PlaybackInputGuard` 也未拒绝。
- 同一会话的无 VAD 转写先后为 2 字 interim、3 字 final，但 Router 均记录为 `chat`，
  所以没有产生 `trusted_unanchored_interrupt_cmd` 或 `explicit_interrupt_cmd`。
- 现有控制词表支持“等等 / 等一下”，未覆盖 FunASR 的常见口语短写“等下”。
- 本次仅把规范化后**完全等于**“等下”的文本作为纯打断别名，并沿用“嗯，你说。”固定回应。
  “我等下再说 / 等下我 / 等下我想问……”仍保持普通聊天，避免短词子串扩大误触发面。

- Router 红测覆盖“等下。”纯控制、“我等下再说”等普通聊天边界。
- 完整无 VAD AEC 回归按真实序列依次发送 `等下` interim 与 `等下。` final，要求只请求一次
  interrupt，且纯控制不得进入 chat；明确 guest 仍须被 TargetSpeakerFocus 拒绝。
- Python 全量 1261 collected，1234 passed、27 skipped；Ruff、Agent strict mypy、
  `git diff --check` 与小程序 32/32 逻辑测试通过。
- 发布后公网 WSS 必须持续发送 20 ms PCM，在 AI speaking 后约 0.6 秒发送
  `/tmp/memoria-wait.pcm`，并在命令开始后同时收到：
  `trusted_unanchored_interrupt_cmd`、`explicit_interrupt_cmd`、
  `assistant_state=interrupted` 与新的 `audio_reset`。
- 任一公网证据缺失立即回滚到 `20260726-133033`。合成 PCM 通过后，真实手机本人声音仍是
  最终物理双讲验收。

## 2026-07-26 实际结果与更正

- 候选早前曾短时切换到生产，因当时的自动门禁未闭环而回滚。更正门禁边界后，
  runtime 于 2026-07-26 20:15:20 CST 再次原子切换到 `20260726-181813`；
  四个 runtime 容器 healthy、restart 0，LiveKit/FunASR/Qwen/Doubao smoke、
  readiness、9/9 core checks、公网 H5/API 与 WMS 均通过。H5 仍为
  `20260723-192611`，真实手机双讲验收仍待完成。
- `a0308a4` 的 Router 修复具有旧红新绿证据：旧版本无法处理“等下。”，新版本的
  Router、InterruptionGuard 与 DuplexRuntime 相关 `112` 项通过；候选全量 Python 为
  `1234 passed, 27 skipped`。
- 上述 `/tmp/memoria-wait.pcm` 公网脚本后来被证明不能模拟真实免提双讲：它向 APM
  提供 far-end reverse reference，但麦克风侧只注入纯近端合成语音，没有手机扬声器产生的
  物理回声、设备时延和非线性失真。APM 因而可能错误削弱短词首部，导致 FunASR 得到
  “一下。”、“你想？”或混入助手残音。
- 因此该合成 WSS 步骤只可用于协议和故障重放，不再作为发布通过门禁。最终验收必须使用
  真实手机外放双讲，并在同一会话同时确认实际停播和
  `trusted_unanchored_interrupt_cmd / explicit_interrupt_cmd / interrupted / audio_reset`。
- 后续离线回归应直接覆盖
  `MiniProgramAudioProcessor.observe_downlink/process_uplink` 的短控制词 onset，
  在时间对齐后检查 correlation、SI-SDR、voiced-ms 与纯回声衰减；测试名称和报告必须明确
  标注 synthetic，不得冒充设备验收。
- runtime 后续于 2026-07-26 21:33:17 CST 回滚到 `20260726-133033`。回滚不代表
  Router 修复被推翻；回滚原因是自动 WSS 夹具无法作为真实手机双讲门禁，且在继续发布前
  还需关闭“助手说等一下 / ASR 缩成等下”导致自我打断的同义回声风险。
