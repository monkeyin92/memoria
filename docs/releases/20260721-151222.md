## 根因与修复

- 生产日志显示，播放期说“等一下”后 LiveKit 未清理控制话轮，确认音、暂停词和后续
  “继续”可能合并为同一 ASR final；Router 又没有状态化 `RESUME`，恢复生成时还会丢失
  原问题和 actual-heard 前缀。
- Runtime 现在按语音 epoch 幂等调用 `AgentSession.clear_user_turn`，Router 统一处理
  enroll / pure interrupt / interrupt+chat / chat / resume，并能识别“好的，好的。等一下。
  继续。”等复合转写。恢复创建新 `GenerationFence`，不复活旧 LLM/TTS task。
- 正式 owner 同 profile 恢复时保留本轮原问题和实际听到的回答前缀；shadow-only 下同一
  shadow profile 仅使用已经在房间播放过的回答前缀，不带入原问题；不同 profile、普通
  uncertain 和 guest 退回普通 chat。缺 current user 或 heard assistant 时 fail closed。
- 人格学习并非未开发。生产 CAM++ 仍是 shadow-only，旧门禁把所有 uncertain 话轮全部
  丢弃，导致长期为 0 traits / 0 versions。注册账号且授权有效的 uncertain 话轮现在只生成
  candidate，必须由主人确认后才发布 v1；guest、匿名、无授权、低质量和 direct archive
  写入仍拒绝。
- uncertain 的声学指标不进入 style stats，不能附着或污染已有 owner/confirmed trait；
  PostgreSQL 对同账户 Persona 写入使用事务级 advisory lock，消除 owner/uncertain 并发
  竞争。shadow-only 实时读取仅允许映射到固定安全描述白名单的已确认低敏表达风格，并
  清空自由文本 context / counterexample / source IDs；私人记忆、旧话轮和工具仍只给 owner。
- H5 将误导性的“尚未发布”改为“正在积累（确认首条特征后生成 v1）”、“N 条待确认”或
  “vN 已启用”。
