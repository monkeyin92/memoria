# Release 20260717-123551

## 目标

修复用户在 `20260717-113441` 上观察到的两类问题：级联轻微滋滋/金属声，以及 Omni 首词缺失后被扬声器尾音反馈触发第二次回答；同时保留上一版真人感 DeliveryPlan。

## 根因与实现

- 级联真人样本的 `packets_lost=0`、`concealed_samples=0`，CosyVoice 原始 24 kHz PCM 也未发现容器头、奇数字节、削波或明显帧跳变。将 LiveKit Opus `max_bitrate` 提高到 64 kbps，保持 24 kHz/mono 与 1.50 秒 endpointing 不变。
- Omni 样本中多次出现 `response.done` 后 8–10 ms 的 `speech_started`，随后自动创建第二个 response，符合助手尾音被麦克风回采形成反馈轮。正常 response 完成后增加 500 ms 实验性反馈保护，并取消保护窗内伪输入引出的自动 response。
- Omni 首轮非静音 concealment 约 15.9%。浏览器支持时尝试设置 `RTCRtpReceiver.jitterBufferTarget=120 ms`；属性不存在、拒绝或忽略时无损回退。
- `session.updated` 后增加 400 ms 欢迎语安静观察窗。用户先开口则抑制欢迎，不向未知 response 发送 cancel；pending、active 与 cancelled response 分离，按 response ID 去重 cancel 并隔离迟到 done。
- 用户开口或 response cancel 时只静音 Omni 的唯一 `<audio>`，继续消费 MediaStream；新合法 response 创建后才恢复播放，避免旧 RTP 缓冲稍后冒出。
- WebRTC 遥测增加丢弃包、NACK、字节数、累计/非静音 concealment 比例、平均 jitter-buffer delay、target/minimum delay 与估算编码码率，并在关键 response 事件额外采样。
- 保留并收紧上一版真人感策略：按最新实际已听回答对齐历史；用户用“可以、好、行”接受提议时直接执行；安全的声学笑声可进入 `light_laughter`；思考式衔接为一次 8–14 字短句并用逗号连接正文。

## 研究结论

- 不把 `semantic_vad` 当作输出首词修复；没有找到阿里官方确认的 Qwen WebRTC 固定吞首词缺陷。
- 当前不新增供应商。腾讯 FlowTTS 是未来最低风险的级联 TTS A/B 候选，但会把中断时的实际已听文本从词级降为句级；百度 Pro、豆包 O2.0/SC2.0 只适合独立端到端 Spike；讯飞 SuperTTS 先做离线试听。
- `jitterBufferTarget` 是兼容性有限的目标值，不是全浏览器保证；500 ms 关麦保护也可能损伤用户立即接话，必须继续用真机矩阵验证。

完整来源与验证矩阵见 `docs/research/realtime_audio_quality_first_word_clipping_research_zh.md`。
