# Memoria Runtime Release 20260817-135129

## 发布目标

- 收敛 Agent/Voice Core 的 generation-bound 委派输出所有权，避免委派失败、超时、取消、空结果或迟到 generation 与普通回复重复输出。
- 补齐 Speaker Authority 稳定策略拒绝的主体能力矩阵，并保持未知 403、5xx 与网络异常按 transport failure fail closed。
- 为 Runtime Profile 拒绝原因提供固定低基数指标；补齐 Media Turn fence、重试、空音频帧和协议合同回归。

## 发布范围

- 生产候选 runtime：Agent、Control API、Speaker Model、Mini Program Gateway、Device Media Gateway 的固定 amd64 工件；实际代码运行变更集中在 Agent/Voice Core。
- H5、小程序源码、ESP32 固件和设备身份区不切换、不刷写、不触发设备语音或电脑外放。
- `jsonschema` 仅加入可复现 dev extra；因 `pyproject.toml`/`uv.lock` 变化，按规程执行本机固定依赖完整构建。

## 发布前门禁

- Agent 全量 `1558`；Control API 全量 `586`。
- Speaker/Router/Runtime Profile 聚焦 `165`；Voice Core 聚焦 `126`；Control Speaker API `4`。
- 固件源码、Device v2 合同、架构状态与验收器 `251`。
- `uv run mypy services --strict`：399 source files；Ruff、Go 全量、模块预算、`git diff --check` 通过。
- `uv sync --frozen --extra dev` 通过；`--all-extras` 的既有 macOS ARM `vosk==0.3.45` 可用性限制不属于本 release 回归。

## 验收边界

本地门禁只证明 `code / wired / local verified`。本 release 不改变
`direct_real_device_verified=false`、`full_duplex_verified=false`，不宣称 Exact DAC、AEC Reference、
双讲、精确 Actual Heard、100/500 轮或 T14 微信独立性通过。部署后仍需以服务器 readiness、容器健康、
业务 API 和错误/指标复核记录 `enabled` 与 `production_runtime_verified`；真实设备和声学验收保持独立。

## 回滚

- 部署前冻结 `/opt/memoria/current` 的实时旧 runtime、旧 env、数据快照和 root-only rollback receipt。
- 直接 runtime 回滚目标以部署前实时读取的 release tag 为准；H5 保持旧软链，本 release 不切 H5。
- 任何 readiness、Provider、容器健康或错误日志门禁失败，按 `docs/production-deployment.md` 的完整 runtime 回滚流程恢复旧 runtime/env；不自动回滚数据库或对象数据。
