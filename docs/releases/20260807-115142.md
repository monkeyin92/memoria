# 显式记忆安全边界修复 Release 20260807-115142

## 根因与修复

- 候选 `20260807-113413` 的 `explicit-memory-v1` 只依赖抽取器标注和不完整敏感关键词；
  `请记住我出生于1990年1月1日。`、`请记住我结婚了。` 可能被自动确认，因此在发布前审阅中
  被拒绝，未上传或切换生产。
- `explicit-memory-v2` 改为 closed allowlist：只有完整 owner fence、单一可回指 self claim，且
  同时匹配服务端可验证的低风险 `preference`/`habit` 模板和完整日常 token 序列时才可自动确认。
  token 外的任何尾缀一律拒绝，避免“喜欢咖啡，因为我患有糖尿病”等把敏感内容夹带进安全前缀；
  未列入 allowlist 的内容默认 candidate。PII、出生/年龄/日期、地点、健康、金融、法律、
  生物特征和关系不再依赖抽取器的 `personal` 标签判断。
- RuleBased 和 Qwen extractor 都只为经过相同 deterministic gate 的显式内容赋予
  `preference`/`habit` predicate。`v1` 自动 confirmation evidence 不获得 `v2` projection rebuild
  授权；既有用户人工 review 保持可重放。

## 发布前门禁

- 新增默认 RuleBased 端到端回归：出生日期、婚姻、健康、金融、法律、生物特征以及安全偏好后
  拼接的敏感尾缀全都进入 candidate review queue；低风险“我喜欢雨天散步”仍可自动确认。
- projection rebuild 现在在截断前要求 pgvector embedder，并复用 Control API 相同的 extractor/
  embedder；独立 pgvector 回归验证配置缺失不会截断、配置存在会重新生成向量文档。
- 本次重新执行 Python、H5、媒体、Go 和远端 CI 门禁，并重新构建所有 commit-bound 工件后才允许
  上传。`20260806-213522` 继续是 runtime/H5 直接回滚点。

## 生产维护

- projection rebuild 须在停止 Control API compiler、Agent、Gateway 和任何启用的 media-runtime
  writer 后，以 root-only `memoria_admin` maintenance DSN 执行；应用 DSN 不具备 `BYPASSRLS`。
  生产当前没有已确认 memory claim，因此 `v1` 到 `v2` 的 fail-closed 升级不会撤销既有确认记录。
