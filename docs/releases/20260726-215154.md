# 小程序“等下”同义回声保护 Release 20260726-215154

## 发布目标

- 保留 `20260726-181813` 对 FunASR 口语短写“等下。”的纯打断支持。
- 修复助手正在播放“等一下”时，回声被 ASR 缩成“等下”后绕过短文本回声门禁、导致
  助手自我打断的问题。
- 不修改 AEC 阈值、Router 优先级、TargetSpeakerFocus、H5 或小程序客户端。

## 根因与修复

- `等下` 是规范化后完全匹配的纯打断别名，但现有 `_looks_like_assistant_echo` 对少于
  4 字的文本直接跳过。
- Runtime 的精确子串检查也无法把“等下”关联到助手正文中的“等一下”，因此该回声可能
  进入可信无 VAD 控制通道；短命令的 TargetSpeakerFocus 允许 unconfirmed explicit control，
  最终可能错误停止当前播放。
- 共享回声门禁现在只增加一条同义映射：ASR 文本完全等于“等下”，且助手正文包含
  “等下”或“等一下”时返回 `assistant_echo`。该判断发生在可信控制准入之前。
- 助手未说上述词时，真实用户“等下 / 等下。”保持纯打断；“我等下再说 / 等下我想问……”
  继续是普通聊天。
- 安全取舍为 fail closed：助手正说“等一下”时，主人只说“等下”也会被保守视为回声，
  可改说“停一下”。这避免短文本在无法可靠完成声纹确认时自我打断。

## 验收边界

- 当前生产 runtime：`20260726-133033`；直接回滚点不变。
- H5 固定 `20260723-192611`；小程序体验版固定 `0.8.49`，本轮无客户端源码变化。
- 合成 WSS 夹具不能模拟手机扬声器的真实回声、时延与非线性失真，只用于区分
  gateway transcription、UI 门禁和 Agent trace，不作为真机通过门禁。
- 最终成功标准仍是真实手机外放双讲：AI 播放约 0.6 秒后说“等一下 / 等下”，实际立即停播，
  同一会话出现 `trusted_unanchored_interrupt_cmd`、`explicit_interrupt_cmd`、
  `assistant_state=interrupted` 与新的 `audio_reset`。
