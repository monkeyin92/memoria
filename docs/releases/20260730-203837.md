# 小程序文字流异步转发 Hotfix 20260730-203837

## 根因

- `20260730-202610` 的公网真实文字 smoke 暴露：Python LiveKit SDK 的
  `LocalParticipant.send_text()` 是 coroutine，小程序网关按同步方法调用，产生
  `coroutine was never awaited`，因此 H5 直连文字路径可用，但小程序 `text_turn` 不会真正进入
  Agent。
- 原测试 participant 使用同步 fake，错误地把接口形态固定成同步调用，未覆盖真实 SDK 契约。

## 修复

- `MiniProgramLiveKitBridge.accept_text_turn()` 改为 async 并 `await send_text()`；
  WebSocket 控制循环同步等待转发完成，再消费下一条控制消息。
- 回归测试改用真正的 async fake 并显式 `await`，防止再次退化为未调度 coroutine。

## 发布边界

- 只切 runtime；H5 继续使用已经验收的 `20260730-202610`，小程序 `0.8.64` 仍只有 dry-run，
  未上传、未提审、未正式发布。
- 上一 runtime 回滚点为 `20260730-202610`；其 H5 与 Agent 文字路径不受此异步问题影响。
- 定向 Gateway 全量测试、Ruff 和 `git diff --check` 通过；候选切流后必须重新跑 Provider、
  readiness、真实 H5 `lk.chat` 和真实小程序网关 `text_turn` 两条公网 smoke。
