# 20260812-103158 Release

## 状态与范围

- 基于生产健康版本 `20260812-003754` 的设备 Path 2 热修。
- ESP32 media challenge POST 现在显式发送 `{}` JSON body，避免边缘代理等待无长度请求直至
  超时并返回 400。
- TURN REST identity 改为 `session_id + device_id` 的固定 SHA-256 scope，不再把冒号分隔的原始
  identity 传给凭据签发器；设备 media session 不再因 identity 格式冲突返回 500。
- 当前实板缺失的 `device_fleet_devices`、活跃证书和 bound event 已从生产 onboarding 与 Identity
  权威行在单事务内回填；回填前备份位于 root-only
  `/var/backups/memoria/fleet-projection-20260812-101843`。
- 该回填只恢复当前测试板。新设备的 onboarding → Device Fleet 可恢复 Saga 仍需使用窄投影函数与
  独立 projector 角色实现；不得把 Fleet maintenance DSN 长期注入 Control，也不得放宽 Session
  Runtime 的 `device_not_registered` 拒绝规则。
- 回滚目标保持 `20260812-003754`；数据库新增行是 forward-only 权威投影，代码回滚不删除。

## 发布门禁

- 固件定向测试 16 项、Control TURN/session 定向测试 54 项、Ruff、严格 mypy 和
  `git diff --check` 通过。
- 固件必须从锁定 xiaozhi `v2.4.2` / ESP-IDF `v6.0.2` 干净 overlay 构建；flash 表只允许
  bootloader `0x0`、partition `0x8000`、OTA data `0xd000`、app `0x20000` 和 assets
  `0x800000`，不得写 `memoria_identity` 的 `0x10000..0x1ffff`。
- 真机烧录后设备身份分区 SHA-256 必须保持
  `b7a717fa399ec1390391ca381b9b86c3202035c71695a95e417a4e0f1d084846`。
- 切流后必须用真实 ESP32 证明 media challenge、media session、设备 WSS、上行语音、Agent
  ASR/LLM/TTS、下行播放与 playback receipt；只通过 HTTP 合同不算端到端完成。
