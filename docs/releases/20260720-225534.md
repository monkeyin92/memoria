# Runtime Release 20260720-225534

## 根因

- 生产 `COSYVOICE_VOLUME=70`，且 `apply_speech_plan()` 会把低于 60 的显式配置重新抬到 70。同文直接 PCM A/B 证实 70 已顶到 0 dBFS 并出现连续削顶，主观表现为滋滋声、发硬和不流利。
- 用户现场会话的 WebRTC 为 0 packet loss、0 concealment，VAD 和 ASR 也正常；网络不是本次音质问题的主要来源。`203120` 已上线的原始 PCM 连续透传在 `214800` 中仍然存在，本次没有重复修改分片归一化。
- 播放期为避免用过短 PCM 误判说话人，声纹聚焦会等待 VAD 端点；但 PlaybackInputGuard 已关闭时，最终转写到达后没有继续完成延迟确认。同时 FunASR 可能把 partial 的“等一下”修订为近音 final，导致明确控制意图丢失，现场最终落入 `target_speaker_rejected`。

## 修复

- CosyVoice 默认及生产音量统一调整为 `45`，降低削顶风险。
- `apply_speech_plan()` 不再篡改显式配置的音量；沿用已上线的原始 PCM 连续透传。
- 控制意图在当前 VAD epoch 内保持粘性；端点后使用完整 PCM 完成目标说话人确认，再执行播放打断，且正确清理过期 pending epoch。
- “等一下”纯控制命令保留简短确认；“等一下+正文”直接进入回答，不再额外播放确认音。
