# 文字话轮无音色 Provenance Hotfix 20260730-204546

## 根因

- `20260730-203837` 已让真实 `lk.chat` 到达 Agent，并生成正确的日期响应计划；随后
  `_bind_response_plan_provenance()` 仍按语音话轮要求存在 generation voice。
- 文字模式已经关闭音频输出且不绑定 TTS 音色，因此 provenance 门禁 fail closed，回复没有产生。
  这不是模型或联网失败，而是语音专属来源约束误套到文字话轮。

## 修复

- `DuplexRuntime` 按精确 `turn_id + generation_id` 暴露已冻结的输入模态，默认仍为 `audio`。
- 仅当同一 fence 的输入模态明确为 `text` 时，允许在没有 generation voice 的情况下绑定
  ResponsePlan provenance；身份、模式策略、回复计划、LLM 来源、generation fence 与历史资格
  均保持原门禁。
- 回归测试在 runtime 存在 TTS、但文字话轮没有 generation voice 的真实冲突条件下断言
  provenance 可绑定，并继续验证助手终稿 `text_delivered=true / heard=false`。

## 发布边界

- 只切 runtime；H5 继续使用 `20260730-202610`，小程序 `0.8.64` 尚未上传。
- Agent unit 全量与 Ruff 通过。切流后须重新跑 Provider/readiness，并以真实 LiveKit SDK 验证
  H5 `lk.chat` 和小程序网关 `text_turn` 均收到文字终稿。
