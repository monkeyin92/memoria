# 小程序无 VAD 语音打断热修 Release 20260726-151122

## 发布目标

- 修复小程序中 FunASR 已识别“等一下”，但 LiveKit 没有产生 VAD start 时仍无法停止 AI 播放的问题。
- 保留既有 FunASR、TargetSpeakerFocus、`UtteranceRouter`、Qwen、Doubao 与 LiveKit 主链；
  不复制 H5 后端，不修改 H5 行为，也不重复上传小程序客户端。

## 根因与修复

- `20260726-133033` 已仅对网关 AEC 会话解除 LiveKit 首轮 3 秒 warmup。生产公网 PCM 验证进一步
  证明：“等一下”已到 FunASR，但没有 VAD start，随后被 `unanchored_playback_transcript` 拒绝，
  所以原有 `UtteranceRouter` 根本没有获得停止当前播放的机会。
- 本次只对带精确 AEC job provenance 的小程序会话开放窄控制通道：最近 900 ms 的 AEC 后 PCM
  至少包含 160 ms voiced，文本必须由 Router 判定为纯打断命令，并通过助手原文/回声、语言与
  backchannel 门禁。该 PCM 仍需走当前 epoch 的 TargetSpeakerFocus；命令不能进入 chat、历史、
  记忆、Persona、工具或敏感权限。
- 每次候选绑定当前 playback epoch。播放完成、新播放开始、AEC 能力撤销都会取消在飞分类并使旧
  epoch 失效，避免播放 A 末尾的迟到结果误停播放 B。
- 网关真实帧 APM 一旦失败，先丢弃故障帧并暂停原始上行，经 LiveKit reliable data 通知 Agent
  单向撤销 trust；只有收到 Agent ACK 后才恢复普通原始 PCM。ACK 超时保持 fail-closed，整场会话
  不得重新启用特权路径。

  H5 默认路径与 Agent 生产接线。
- Python 全量 `1224 passed, 27 skipped`；核心竞态连续 20 轮通过；Ruff、strict mypy
  （156 个 source files）与 `git diff --check` 通过。构建工件必须由本 tag 的干净
  commit 生成并通过服务器 manifest/verifier、隔离 smoke 与 Linux/amd64 APM 探针。
- 发布后 readiness 必须绑定 `20260726-151122`，四个 runtime 容器 healthy，H5 软链不变。
- 公网合成 PCM 必须在新的 AI speaking 后约 0.6 秒发送“等一下”，并在命令开始之后同时观察：
  `trusted_unanchored_interrupt_cmd`、`explicit_interrupt_cmd`、`assistant_state=interrupted` 与新的
