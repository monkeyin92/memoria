## 目标与根因

同一 iPhone 使用 `0.8.55` 后仍显示泛化的“connection refused”。已确认的失败放大链路包括：

1. `startVoice()` 在 `setData({connecting: true})` 的异步 UI 更新生效前可被重复进入，造成短时间内
   多次创建 session；
2. TLS header 已认证时，旧客户端仍可能等待 LiveKit bridge 建连完成才得到任何应用层反馈；
3. 真机 `SocketTask` 的 `onOpen`、首个 PCM、`onError` 和 `onClose` 可能乱序，导致迟到 `hello` 被误判
   为协议错误，或 `4401/4400` 被泛化成“connection refused”；
4. `8443 → 9443` stream 转发使内层 Nginx 看到 loopback 地址，第四次 session 创建曾命中原
   `burst=3` 限流。这是放大因素，不以不安全的 header 身份限流替代认证后的账号限流。

## 候选改动

- 小程序 `startVoice()` 使用单飞 Promise；同一启动未结算前的后续点击复用同一 Promise。
- 客户端保留 TLS Upgrade header，并在 `onOpen` 发送既有 v1 JSON `hello` 作为跨版本回退；收到
  `ready` 后不再补发 `hello`。
- Gateway 在 header 或 hello 认证成功后先发送无敏感数据的 `handshake_ack`，再连接 LiveKit bridge
  并发送 `ready`；header 认证路径只允许一次精确的迟到 v1 `hello`，即使首个 PCM 已先到达。
- 若 `SocketTask.onError` 先到，客户端最多等待 100 ms 给 `onClose` 传递 `4400/4401/1011`；只有未收到
  close 时才显示平台原始连接错误。
- 精确 `/memoria-api/v1/sessions` 由 `memoria_session burst=3` 调整为同一 `10r/m` 下的 `burst=6`，
  为单次 ticket 刷新保留有界缓冲。未把未验证的 `Authorization` header 用作 Nginx key。
- Gateway 仅记录 `transport`、`ack_sent|ready_sent` 和耗时，不记录 ticket、PCM、文本或 cookie。
