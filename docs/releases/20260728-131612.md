# 小程序握手确认竞态修复 20260728-131612

## 根因

用户关闭 VPN 后出现“connection refused”时，服务器取证已证明部分请求完成 WebSocket Upgrade 并进入
Gateway。Gateway 先发送 `handshake_ack`，随后才等待 LiveKit bridge 完成并发送 `ready`；但小程序此前
会在泛化 `SocketTask.onError` 后仅等待 100 ms，再直接拒绝连接。有效 ack 没有取消该待处理错误，因此
bridge 只要超过 100 ms 就会让客户端先失败；迟到 `ready` 还可能在已失败的会话中重新启动录音。

这不是全局 8443/DNS/Nginx 故障。443 外部路径也尚未完成稳定验证，因此本次不迁移端口、不修改 WMS 或
服务端入口。

## 修复

- 把有效 `handshake_ack` 视为已认证的传输确认：取消此前泛化错误，并在等待 `ready` 时忽略其后的泛化
  `onError`；具体 WebSocket close code 仍优先处理。
- 添加 10 秒 bridge-ready 上限，超时返回明确的 `gateway_ready_timeout` 并关闭 socket。
- 为连接拒绝、关闭、显式 close 与 ready 建立终态围栏，禁止超时/拒绝后的迟到 `ready` 重启录音。
- 将“请关闭 VPN/代理”改为中性提示：建议切换网络，或分别尝试开启/关闭 VPN/代理。

## 验证与发布

- 回归用例覆盖：`onError → handshake_ack → ready`、ack 后迟到泛化 error、ready 超时和迟到 ready 围栏。
- 小程序完整测试 `58/58`、相关 JavaScript syntax check、`git diff --check` 通过。
- 客户端体验版 `0.8.57` 已在微信开发者工具确认后上传成功（约 600 KB）；服务端保持已上线
  `20260728-123528`，无需再次部署。
- 上传后必须在同一 iPhone 关闭 VPN 实测一次：Gateway 应记录 `ack_sent` 后 `ready_sent`，页面进入
  listening；若仍失败，以该时段的脱敏日志和原始错误继续定位。
