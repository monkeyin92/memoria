# 小程序迟到转写声学 witness 热修 Release 20260726-161236

## 发布目标

- 修复 AEC 后已存在真实有声片段，但 FunASR 无 VAD 转写稍晚到达时，“等一下”仍因最后
  900 ms 已被静音覆盖而无法打断 AI 的问题。
- 保持 `UtteranceRouter`、TargetSpeakerFocus、播放 epoch、AEC 运行期撤销与 H5 默认路径不变；
  不降低 voiced 能量阈值，不复制第二套意图或媒体后端。

## 根因与修复

- 失败候选 `20260726-151122` 的公网会话证明：AEC provenance、故事 ASR、Qwen、Doubao 与
  播放均正常，但播放期无 VAD 转写在到达时只重新扫描 PCM 尾部。有效语音结束后约一秒的静音
  足以让 900 ms 尾窗失去 160 ms voiced，随后仍被隔离为
  `unanchored_playback_transcript`。
- Runtime 现在只在小程序 AEC 会话且 AI 正在播放时，将满足“900 ms 内至少 160 ms voiced”
  的 AEC 后 PCM 冻结为当前播放 epoch 的短期 witness。FunASR 转写在 2500 ms 内到达时复用
  该 witness 进入既有 Router 与 TargetSpeakerFocus；分类使用冻结的有声窗口，而不是迟到时
  已被静音覆盖的滚动尾部。
- VAD start、播放替换/结束、AEC trust 撤销和当前转写丢弃统一清除 witness。过期 witness、
  静音/底噪、普通聊天、interrupt+chat、助手原文/回声、旧播放 epoch 与 H5 仍保持 fail closed。
- AEC provenance 会话无论部署 profile 都启用既有 PlaybackInputGuard；非 AEC/H5 会话保持原逻辑。

## 发布边界

- runtime 回滚基线：`20260726-133033`。
- 失败候选 `20260726-151122` 不得重新激活。
- H5 固定保持 `20260723-192611`；小程序体验版固定保持 `0.8.49`，本轮无客户端源码变化。
- 正式环境继续保持 `MINIPROGRAM_GATEWAY_AEC_ENABLED=true`，Agent 不设置全局
  `INTERRUPTION_MIN_DURATION_S` 覆盖。

## 门禁与验收

- 最小红测固定“200 ms voiced + 1.2 s silence + 无 VAD 等一下”，修复前稳定返回 `wait`，
  修复后必须 `accept` 且 TargetSpeakerFocus 获得的 witness 仍含至少 160 ms voiced。
- 负向覆盖 witness 2500 ms 过期、静音/低噪、不足 voiced、普通聊天、interrupt+chat、
  助手原文、AEC 撤销、播放 epoch 迟到，以及 `livekit_cloud` 下 AEC 会话 guard 接线。
- Python 全量 `1227 passed, 27 skipped`；Ruff、Agent strict mypy、`git diff --check`
  与小程序 32/32 逻辑测试通过。真实 80 ms FunASR 分块的 witness 统计实测约
  `0.18 ms/chunk`，单会话约占一个 CPU 核 `0.22%`。
- 公网 WSS 必须持续发送 20 ms PCM，在 AI speaking 后约 0.6 秒发送“等一下”，并在命令开始后
  同时收到 `trusted_unanchored_interrupt_cmd`、`explicit_interrupt_cmd`、
  `assistant_state=interrupted` 与新的 `audio_reset`。任一缺失立即回滚。
- 自动化合成声音不能替代真实手机本人声音的物理扬声器/麦克风双讲终验。
