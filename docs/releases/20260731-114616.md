# 实时联网查询修复 Release 20260731-114616

## 目标与根因

- 修复用户询问“今天南京天气怎么样”后被回答“不能查询”的线上回归。生产会话已确认请求正常
  到达 Qwen、没有超时或打断；但共享对话模型是 `qwen-turbo`，百炼当前模型能力页明确标为
  不支持联网搜索，传入 `enable_search=true` 不会赋予该能力。
- 上一版完成态还没有把“暂时不清楚／不能查询／没办法直接查”等自我拒答识别为未完成，因而会
  清掉实时待办，使紧随其后的追问退化成普通闲聊。

## 实现与边界

- 普通对话继续使用 `qwen-turbo`；仅已识别的天气、新闻、行情等实时请求，使用独立
  `qwen-plus` OpenAI-compatible 调用，并设置 `enable_search=true`、
  `search_options.forced_search=true` 和 `search_strategy=turbo`。
- 独立调用只发送固定安全提示与当前 `PendingRealtimeRequest.query`，不发送历史、主人资料、
  记忆、工具、会话 ID 或其他私有上下文；结果仍经过既有 GenerationFence、语音预算与
  owner/public scope 门禁。
- Provider 超时、非 2xx、坏响应、空响应或自我拒答统一播报“我不知道。”并保留待办；相邻同一
  scope 的“人呢／查到了吗／你不能帮我查吗”可重试原公开问题，新话题、跨 scope 或迟到 generation
  仍丢弃待办。
- 仅计划切换 runtime；H5 与小程序源码、体验版和正式版均不改动。

## 发布前证据

- 精确回归先红后绿：覆盖“不能查询”“暂时不清楚”“没办法直接查”和“你不能帮我查吗”的连续
  对话；独立 resolver 单测锁定强制搜索 payload、仅当前 query 的隐私边界、失败降级和超时。
- `services/agent/tests/unit` 全量通过，Ruff、strict mypy 和 `git diff --check` 通过。
- 生产凭据的只读 provider canary 已用 `qwen-plus`、强制搜索和公开问题“今天南京天气怎么样？”
  返回 HTTP 200、约 5.63 秒、直接给出当天南京天气；未输出或记录密钥。
