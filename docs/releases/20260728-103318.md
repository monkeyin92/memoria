# 小程序 WSS Upgrade header 握手 Release 20260728-103318

## 发布目标

修复同一 iPhone 已完成 TCP、TLS 与 WebSocket Upgrade，却没有执行
`SocketTask.onOpen → JSON hello`、约 2.9 秒后主动关闭连接的问题。生产网关需要先兼容
新的 TLS Upgrade header 握手和旧版 JSON `hello`，再上传小程序体验版，避免新旧版本互相
不兼容。

## 候选内容

- 小程序通过 `X-Memoria-Gateway-Protocol`、`X-Memoria-Gateway-Ticket` 和
  `X-Memoria-Downlink-Generation` 请求头传递既有短期签名 ticket 与下行能力；ticket 不进入 URL。
- Gateway 在 Upgrade 后优先验证 header ticket 并发送 `ready`，仍保留旧客户端首条 JSON
  `hello` 回退。
- socket 错误仅在纯 `connection refused` 时标识为该类别；含 timeout 的混合错误不再错误刷新
  ticket。
- 共享媒体契约、Python/JavaScript 回归测试和网关 ADR 同步更新；Nginx 保持默认请求头透传，媒体
  location 继续关闭 access log。

## 发布前验证

- 网关定向测试：`6/6` 通过；含 header 成功、无效 header 拒绝和旧 JSON `hello` 回退。
- 小程序测试：`51/51` 通过。
- `ruff`、`mypy services/miniprogram_gateway/app.py`、JavaScript syntax、JSON 解析与
  `git diff --check` 通过。
- 真机抓包证据、问题边界和候选设计见
  `docs/releases/20260728-095500-miniprogram-wss-diagnostic.md`。

## 激活与验收

1. 从此 release tag 生成 commit-bound source、镜像和 H5 工件，服务器校验 manifest 后先切
   runtime；H5 不变时不切换现有 H5 软链。
2. 以无效 header ticket 的 WSS smoke 验证 Nginx 到 Gateway 的 header 透传和 `4401` 拒绝。
3. 上传小程序 `0.8.55` 体验版，在同一 iPhone 点击“开始语音陪伴”；期望不再出现网络拒绝，
   并能收到 gateway `ready`。
4. 成功后仅删除本轮 `/tmp` 抓包、构建和上传临时工件；不执行广泛 Docker prune，不删除数据卷、
   数据库、用户未跟踪文件或其他项目资源。

## 回滚

若 runtime readiness、WSS smoke 或真实设备连接失败，恢复发布前记录的 runtime 软链和四份
root-only env 备份，并执行 `docker compose up -d --no-build` 与 readiness 刷新。旧版小程序仍使用
JSON `hello`，因此回滚 runtime 后可继续服务 `0.8.54`；不得让 `0.8.55` 指向旧网关。
