# 小程序播放期显式打断竞态热修 Release 20260725-211256

## 发布目标

- 消除“停一下”已被 Router 判定为明确控制语后，先恢复 LiveKit 自动打断阈值、再异步停止
  播放的竞态。
- 让播放期明确控制语始终先走受控的停止回调；自动阈值只在没有可用停止回调时才作为回退。

## 根因与修复

- `DuplexRuntime` 曾在播放期接受候选输入后先将 `min_words` 恢复为基础值。LiveKit 自动
  打断可以在异步控制回调之前抢先触发，使实际行为依赖事件调度顺序，无法证明“停一下”走了
  Router 的确定控制路径。
- 现在先请求已接线的 LiveKit 停止；回调成功挂起后保持播放保护阈值，`on_real_interrupt`
  完成后统一恢复基础阈值。没有停止回调时才恢复原阈值继续走既有回退。
- 回归测试固定“停止回调观测到 `min_words=1000`”以及“迟到的 playback completion 不得把
  截断的已听文本覆盖为完整旧回复”。

## 发布前验证

- Agent production wiring、TargetSpeakerFocus、PlaybackInputGuard、UtteranceRouter 与
  小程序网关相关测试通过；Ruff、strict mypy 与 `git diff --check` 通过。
- 小程序逻辑测试 15/15 通过；本轮没有小程序源码变更。
- 前一 runtime `20260725-203826` 的公网合成小程序会话已验证媒体票据、下行播放、播放中
  “停一下”、generation `audio_reset` 和 `assistant_state: interrupted` 全链路可达；
  本次发布后将复测其日志原因必须为 `target_speaker_confirmed`。
