# 小程序打断重放抑制与话轮延迟 Release 20260726-233337

## 发布目标

- AI 播放期间用户说“停一下”后，若 FunASR endpoint final 只重放上一条用户问题，
  立即按控制话轮收口，不再创建第二个 LLM 回答。
- 保留“嗯，你说。”确认音，并让 suppression/yield 事件准确记录
  `interrupt_replay / interrupt_replayed_previous_turn`。
- 修正生产 endpointing 配置漂移，把自建链路从 `1.50 / 2.20` 收敛到代码既有目标
  `0.90 / 1.50`；`FALSE_INTERRUPTION_TIMEOUT_S` 保持 `1.70`。

## 真机根因

- 取证会话：`c67bc334-6ba9-428c-a76c-7bc67e86427d`。
- root-only 归档：
  `/var/backups/memoria/device-session-20260726-20260726-224112/`。
- 第一次“你叫什么名字？”对应 gen4；用户打断后，ASR 又提交了相同 final，形成 gen6。
  服务端没有旧 generation 复活或双 TTS，问题是第二个相同用户话轮被重新提交。
- 该 speech epoch 的 sticky route 为 `interrupt_then_chat`，所以旧实现既不会播放纯控制
  确认音，也会让重放 final 进入 LLM。
- 同一会话多次 `end_of_turn_delay=2.200s`；容器实参仍为
  `ENDPOINTING_MIN_DELAY_S=1.50 / ENDPOINTING_MAX_DELAY_S=2.20`，覆盖了代码中
  `0.90 / 1.50` 的自建默认值。

## 实现

- `UtteranceRouter` 新增 `INTERRUPT_REPLAY`，统一接收当前 speech epoch 的 sticky
  interrupt route 和上一已提交用户文本。
- 精确重放优先于普通 explicit+content；即使上一问题本身以“不是 / 不对”等词开头，
  也不会再次进入 chat。
- Runtime 只保存会话状态，并统一按 `should_interrupt / enter_chat` 执行 clear、
  paused reply、确认音和 StopResponse，不再新增平行意图规则。
- 非播放期重复同一问题、播放期真正的新问题、纯控制词和 enrollment 优先级保持不变。
- endpointing 默认值集中校验；生成脚本、开发示例、生产模板和发布手册统一为
  `0.90 / 1.50 / 1.70`，`verify_env` 拒绝非有限值、`min > max` 和
  `false timeout < min`。

## 边界

- LiveKit `TurnDetector v1-mini` 负责判断“用户何时说完”，不是
  `stop / resume / chat` 意图分类器。
- 本次没有增加新的停词列表，也没有把停止动作改成 LLM 路由。停止仍走低延迟、确定性、
  fail-closed 快车道；后续如需模型语义，只应辅助 ambiguous final。
- 两轮真实样本的 transcription delay 已达 `2.13s / 2.34s`，下调 endpoint max
  不能消除供应商转写延迟。真机仍需覆盖慢语速、1–2 秒句中停顿和长句，防止拆轮。
- H5 与小程序源码不变；生产 H5 继续固定 `20260723-192611`，小程序体验版继续
  固定 `0.8.49`。

## 真机验收

1. AI 回答中说“停一下”，确认立即停播并只说一次“嗯，你说。”。
2. 不再重复回答上一问题；随后提出真正新问题可正常回答。
3. 正常短句、长句、慢语速和 1–2 秒句中停顿不被错误拆轮。
4. 同一会话核对 `interrupt_replay`、单次 ack、单次 generation bump 和 endpointing
   实际值；回滚前先冻结 Agent/Gateway/Control 脱敏日志。
