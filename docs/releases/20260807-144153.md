# H5 回复深度、打断恢复与回顾同步 Release 20260807-144153

## 发布范围

- 实时公开检索默认采用 brief 回复策略：先整理检索结果，再用几句短话给出结论、关键耗时
  和必要注意事项；只有用户明确要求详细、完整或继续展开时才提高回复预算。普通对话和受控
  话轮沿用各自的字数/句数上限，表达深度指令并入唯一的 canonical response-plan system block。
- H5 播放期的“好了，知道了”等结束确认统一进入 `UtteranceRouter` 控制路由；接受的 barge-in
  final 保留为 playback-contaminated candidate，使后续 canonical endpoint 能从助手回声中提取
 真实用户短句，而不是丢弃整段 speech epoch。
- H5 消息保存暴露可等待的 persistence fence。结束会话、生成每日回顾和加载日期列表前先排空
 进行中的保存；回顾页始终保留今天的日期入口，切换旧日期不会移除今天。没有
  `history_eligible=true` 主人话轮时，页面明确显示等待状态，不把不确定说话人内容伪造为主人回顾。

## 根因证据

- 南京到上海规划的生产检索结果约 336 字，并直接进入语音输出；旧 delivery mode 还会把预算
  放大到 560 字，缺少独立的实时紧凑回答契约。
- 播放中打断的旧 generation 被取消，但污染后的 ASR final 在 `SpeechEpochAssembler` 中被整段
  丢弃，日志表现为 `canonical_len=0 discarded_epochs=1`，不是网络连接卡死。
- H5 日期栏只在当前选中日期缺失时注入今天占位；点击旧日期后该占位从 DOM 消失。消息保存和
  自动摘要没有共同的完成 fence，摘要可能抢在最后一条消息写入前执行。
