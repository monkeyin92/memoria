# 短期上下文与情绪化语音 Release 20260729-185111

## 目标

- 修复未确认说话人时短追问丢失本次会话上下文的问题，同时继续隔离主人私人历史、记忆、Persona 与工具权限。
- 将同一用户话轮的多段声学情绪合并为一次有 generation fence 的观察，并让唯一的 LLM/TTS 控制面承接自然口语表达。
- 为豆包 TTS 2.0 增加受控情绪、方言、语气、语速、音调与“只理解不朗读”的引用上文；个人复刻音色继续禁用上下文控制。

## 发布前门禁

- 完整 Python pytest、Ruff、strict mypy、离线 E2E 与 `git diff --check` 必须通过。
- 发布工件只取本 release tag 指向的干净 commit；小程序本地未跟踪资产、上传脚本和 lockfile 不进入工件或提交。
- `DOUBAO_TTS_STYLE_CONTROL_ENABLED=true` 只在五个批准音色的真实豆包风格合成都返回非空音频、原始字级时间戳 `alignment_status=ok`，并分别通过 FunASR 回识别目标正文且未朗读引用上文后启用；开关缺失或关闭时 required smoke 必须失败。

## 生产变更

- 仅切换 runtime；H5 继续指向 `20260729-113831`，小程序不上传、不提审、不发布。
- 四个 `linux/amd64` runtime 镜像、source archive、候选 H5、manifest 与 verifier 绑定同一 commit/tag，并先在服务器隔离 smoke。
- 切换前创建 SQLite 一致快照、PostgreSQL custom dump 与四份 root-only env 备份；生产 Agent env 只新增非 secret 风格开关。

## 验收

- Provider smoke 必须覆盖 LiveKit、FunASR、Qwen、豆包普通合成、豆包风格+引用上文、取消与 Interrupt Semantic，并刷新绑定本 tag 的 readiness。
- 验证四个 runtime 容器健康且无重启，公网 `8443` H5/API ready 与 WMS 静态页正常；H5 软链保持原值。
- 本轮服务端 canary 覆盖五个批准音色的协议、时间戳和回识别门禁，但不等同于真机端对自然度、方言准确度、情绪强度和真实笑声的主观声学验收。

## 回滚

- runtime 故障先恢复本轮 env 备份，再把 `/opt/memoria/current` 原子切回切换前实时读取的 tag，执行 `docker compose up -d --no-build` 与 readiness 刷新。
- 不自动回滚 SQLite、PostgreSQL 或 MinIO；先冻结现场并保留本轮数据与工件。
