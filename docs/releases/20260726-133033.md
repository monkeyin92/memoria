# 小程序首轮语音打断 warmup 热修 Release 20260726-133033

## 发布目标

- 修复小程序中 AI 开口后最初约 3 秒内说“等一下”仍无法打断的问题。
- 保留网关 AEC 与既有 `UtteranceRouter`、TargetSpeakerFocus、FunASR、Qwen、Doubao、
  LiveKit 媒体链路，不复制 H5 后端。
- H5 继续使用 LiveKit 默认 AEC warmup；本次不修改或切换 H5，也不重复上传小程序包。

## 根因与修复

- 当前固定的 `livekit-agents==1.6.5` 中，`AgentSession` 默认
  `aec_warmup_duration=3.0`。首次进入 `speaking` 后，该时段会把 STT 输入替换为静音，
  并拒绝基于音频活动的 interruption。因此短词上行、VAD 和 Agent 链路即使正常，首轮
  “等一下”仍不会进入既有打断控制面；持续数秒后的长语音则可以打断。
- 小程序媒体网关已有独立 WebRTC APM。网关仅在本会话 APM 初始化且 10 ms 静音
  reverse/capture 自检成功时，通过
  LiveKit `RoomAgentDispatch.metadata` 发送版本化能力标记；Agent 只对该 job 设置
  `aec_warmup_duration=None`。
- AEC 关闭、初始化失败、未知标记或普通 H5 dispatch 都不携带该能力，继续保留 LiveKit
  默认 3 秒保护。策略归属绑定 immutable job provenance，不扫描房间 participant，避免
  参与者重连或混合客户端改变整个 AgentSession。
- Token 内 dispatch metadata 只负责唯一 session room 的新 job 启动；既有房间重连复用
  已启动的 AgentSession，而 LiveKit 的一次性 warmup 不会因 participant 重连重新开始。

- 定向回归覆盖：网关 AEC 成功、关闭、初始化失败、首次处理失败，H5 默认 warmup，
  未知能力 fail closed，
  Agent entrypoint 接线，以及 TargetSpeakerFocus、`UtteranceRouter`、DuplexRuntime。
- Python 全量：`1206 passed, 27 skipped`；定向语音/网关回归：`171 passed`；Ruff、
  strict mypy（156 个 source files）与 `git diff --check` 通过。
- 发布后 readiness 必须绑定 `20260726-133033`，四个 runtime 容器 healthy，H5 软链不变；
  新小程序会话必须同时出现 `mini_program_aec_ready` 与
  `mini_program_session_audio_policy aec_warmup_duration=disabled`。
- 公网合成 PCM 在 AI speaking 后约 0.6 秒发送“等一下”，必须观察
  `barge_in_detected → explicit_interrupt_cmd → interrupted → audio_reset`。真实手机仍需在
  同一会话复测；自动化或开发者工具不能替代物理扬声器、麦克风和外录验收。
