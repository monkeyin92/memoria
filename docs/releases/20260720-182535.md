# Runtime/H5 Release 20260720-182535

## 目标

修复声纹 onboarding 完成后，首次对话仍再次要求登记声纹，以及首次用户语音触发后欢迎语音色从已选伙伴音色回退到全局基线的问题。

## 根因与修复

- 生产同时开启了遗留的会话级 `SPEAKER_VERIFY_ENABLED` 和正式 `SpeakerAuthority`。前者每次会话无条件重新登记，未读取 H5 注册阶段建立的 shadow 声纹。
- `on_user_voice_started()` 原先立即切回 `warm_companion`，再异步刷新已选伙伴的声音档案，导致用户选择的 `bright_peer` 在首个回答前后发生音色跳变。
- 正式 `SpeakerAuthority` 开启时，Agent 现在自动禁用遗留会话登记；H5/Omni 浏览器本地重复登记默认关闭。
- 声音档案刷新改为后台进行，刷新完成前保留当前已生效音色，并在下一次 TTS 边界前等待；仅在刷新失败或没有档案时降级到基线。
- 生产同时修正 `/var/lib/memoria-agent` 为容器 UID `65532` 可写，消除 Agent spool lock 的权限错误。
