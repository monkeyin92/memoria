# 将数据库、对象、密钥和投影作为一个联合恢复合同

Memoria 的终身档案不是单一数据库：PostgreSQL 保存证据、权限和对象引用，S3/OSS 保存加密媒体，KMS/密钥系统决定密文能否恢复，人物、时间线、知识与人格又是可重建投影。因此恢复不能以 `pg_restore` 成功或对象下载成功分别判定，而必须在同一恢复点中联合验证数据库清单、对象明文哈希、密钥版本、投影重建、孤儿引用和账户隔离；任一项失败都不得切换生产流量。

## Considered Options

- 只验证 PostgreSQL 备份：最简单，但会把对象或密钥缺失的档案误报为可恢复。
- 数据库、对象和密钥分别演练：便于分工，但不能证明它们属于同一恢复点，也无法发现跨底座孤儿引用。
- 将所有媒体直接写入 PostgreSQL：恢复面更少，但放大数据库容量、备份窗口和密钥隔离成本。

## Consequences

- 每个恢复点必须有数据库 dump/WAL、对象清单和密钥版本的共同标签与 SHA-256 证据。
- 空环境恢复后必须重建投影、执行外键/孤儿检查和 RLS 账户作用域检查。
- 生产演练未同时覆盖 PITR、S3/OSS 与 KMS 前，只能宣称本地工程合同通过。
- 自动化报告保存计数、哈希、RTO 和失败项，不保存 DSN、secret 或明文敏感内容。
