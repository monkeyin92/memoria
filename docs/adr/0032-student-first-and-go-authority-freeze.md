# 学生第一站与 Go 权威迁移冻结

## 背景

Memoria 的记忆、人格、证据账本和全双工语音编排已能复用，但学生产品线尚缺少未成年账号、监护人同意、功能白名单和学生域。同时，Go StreamCore 权威迁移仍需要多实例 ownership、shadow parity、容量、chaos 和回滚证据。在有限产能下同时推进两条主线，会延后学生场景必须先具备的合规边界。

## 决策

1. 学生线是当前第一产品站。交付顺序固定为 P0 治理止血、P1 未成年合规层、P2 学生导师域、P3 情绪陪伴与家长周报及危机链。新能力复用现有账号门禁、模式冻结、`UtteranceRouter` 和 evidence ledger，不在 `duplex_runtime.py` 增设平行控制路径。
2. Go StreamCore 权威迁移立即冻结。`architecture-status.yaml` 必须保持 `go_authoritative_allowed: false`；允许既有 shadow 路径继续收集无副作用证据，但暂停 A6B 切权、多实例 ownership、容量、chaos 和灰度迁移的新功能投入。
3. P1 是学生功能对外的硬门禁。P1 白名单矩阵、监护人同意与撤回、未成年会话签发、声纹/声音复刻/数字分身/Legacy/账号级进化禁用以及数据隔离未全部验收时，任何学生功能都不得进入生产、公开体验或对外宣传。缺失账号类别或同意证据时必须 fail closed。
4. 成人线的数字分身、Legacy 和自我进化保留现有能力，冻结新特性，只接受安全、隐私、删除与生产故障修复。

## 解冻条件

Go 权威迁移只能在以下条件同时满足后重新立项：

1. 学生线 P3 已验收，且 P1、P2 的发布门禁仍保持通过；
2. 团队有明确的独立产能，不挤占学生线安全、合规和产品验收；
3. 产品负责人和架构负责人做出显式解冻决策，以新 ADR 与 `architecture-status.yaml` 变更留痕。

解冻不等于允许切权。ADR-0029 规定的固定评测集 parity、真实容量/SLO、单写者、无副作用 shadow 证据和回滚演练仍是独立前置条件；在它们全部通过之前，`go_authoritative` 继续 fail closed。

## 结果与代价

该决策把产能集中在学生市场的入场券，并防止尚未合规验收的功能被客户端隐藏等弱边界绕过。代价是 Go 迁移时间表不再连续，成人线增量特性也暂停；已有安全修复、运行观测与无副作用 shadow 证据不受影响。
