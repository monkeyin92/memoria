# 声音 A/B 盲测映射只保存在服务端

若 H5 收到哪个槽位是复刻候选，所谓盲测会被界面、网络检查或先入为主偏差破坏；若客户端还能提交首包、取消尾音和时间戳误差，则可伪造客观质量并激活不合格声音。Memoria 因此由服务端随机生成 A/B 映射，客户端只获得 trial ID、槽位和同文试听；主人提交偏好后由服务端解析候选是否胜出。主观评价与可信服务端质量探针分开存储，两者都通过且授权仍有效时才能激活。

## Considered Options

- H5 本地随机 A/B：实现直接，但映射可见且刷新、跨设备和审计一致性差。
- 不做盲测，直接让用户试听复刻音：流程更短，但“这是我的声音”的标签会显著影响相似度和自然度判断。
- 客户端同时上报主观和客观指标：接口更少，但浏览器不能可信测量 Provider 首包与取消尾音，也可被篡改。

## Consequences

- `candidate_slot`、供应商 voice ID 和声音对象密钥不进入普通 API 响应或账户导出。
- A/B 两槽使用同一文本与无缓存音频响应；trial 归属账户且只能用于对应 profile。
- 选择基线槽位不能让候选通过；没有服务端质量证据时激活返回冲突。
- 盲测解决流程偏差，不替代真人样本、设备矩阵和长期自然度评估。
