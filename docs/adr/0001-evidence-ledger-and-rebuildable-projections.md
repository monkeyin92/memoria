# 以证据账本作为唯一原始记录，其他记忆均为可重建投影

Memoria 采用追加式 `Evidence Event` 保存转写、播放事实、说话人结论、纠错和授权变化；人物、关系、时间线、知识与人格不直接充当原始记录，而由带版本的编译过程生成。这样可以保留“用户说过什么”和“模型推断了什么”的边界，支持纠错、冲突、撤销和算法升级后的重建；代价是需要维护投影版本、幂等消费和重建流程。

## Considered Options

- 只保存聊天消息和每日总结：实现最简单，但无法可靠处理来源、纠错、冲突和人格污染。
- 直接将模型抽取结果覆盖到 Profile 字段：读取快，但会丢失历史证据，也无法解释或回滚错误推断。
- 全量事件溯源所有运行状态：审计能力最强，但会把实时控制状态和长期档案耦合，当前成本过高。

## Consequences

- 账本只追加；纠错和删除通过新事件、密钥销毁及投影重建表达，不静默改写历史。
- `candidate / confirmed / disputed / retracted` 是记忆声明状态，不是真假二元标签。
- 投影必须记录编译器版本和源事件 ID，并可从账本确定性重建。
