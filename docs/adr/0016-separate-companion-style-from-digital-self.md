# 陪伴者风格与证据成长的数字分身相互独立

## Context

完全空白的前台助手无法稳定建立信任、主动采访或帮助用户开始表达；强预设人格虽然更容易制造第一印象，却会用自己的价值观、问题结构和语言习惯污染最终形成的“数字你”。现有五个伙伴已经承担视觉、声音和陪伴入口，但 Persona、记忆与声音资产必须继续只代表账户主人。

## Decision

采用“轻人格陪伴者 + 空白成长数字分身”的混合方案：

- 陪伴者拥有稳定但克制的工作风格，只控制温暖程度、直接程度、回复长度、提问频率和访谈深度；不得拥有会影响用户画像的独立人生经历、价值排序或强判断倾向。
- 数字分身初始不含任何伙伴人格，只能从账户主人的权威表达、真实选择、明确确认、纠错和负面证据中成长。
- 陪伴者学习“怎样更好地陪你”，数字分身学习“你是谁”；两者使用独立数据、版本和运行策略。
- Self Preview 和 Legacy 不加载最初伙伴的风格，只加载最小安全宪法、指定 `DigitalSelfVersion`、来源边界及获批关系画像。
- 助手生成文本、引导性问题和模拟回答不能直接成为主人证据；只有主人明确确认后的内容才能升级。

## Considered Options

- 完全空白助手：避免显式人格污染，但模型仍有隐式默认风格，且冷启动、留存与访谈能力弱。
- 强角色 Soul：首日吸引力强，但长期会把角色价值观和表达方式混入主人模型，传承时得到的是混合人格。

## Consequences

- 伙伴可随时更换而不改变已形成的数字分身版本。
- H5 必须把“选择机器人性格”表达为“选择陪伴方式”，并分别展示陪伴适应与数字分身成长。
- 所有模式权限和数据注入由服务端决定，前端标签不能成为安全边界。
- Archive 只负责浏览与审核；Self Preview/Legacy 必须绑定不可变版本并持续披露数字身份。
