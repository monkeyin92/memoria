# 以稳定账号身份作为声纹、记忆、人格和声音档案的归属根

Memoria 使用服务端稳定 `user_id` 作为长期资产归属根，并提供最小用户名/密码注册与登录。用户名经 NFKC 规范化和大小写折叠后使用数据库唯一约束；密码以随机盐 scrypt 哈希保存。已有匿名身份携带有效 Bearer 注册时原地升级，不更换 `user_id`，因此原聊天、Profile 及后续声纹、人格和声音档案不会因注册而换主键。

账号身份只证明客户端持有账号凭据。麦克风前的现实说话人仍由 `SpeakerAuthority` 独立给出 `owner / guest / uncertain`，敏感动作继续结合设备状态和必要的二次确认；登录成功不能直接升级为主人声纹结论。

## Considered Options

- 永久依赖浏览器匿名身份：实现最少，但清理存储、换设备或令牌失效后无法可靠恢复原档案。
- 注册时创建全新 `user_id` 并复制匿名数据：边界直观，但复制中断、双重归属和引用迁移风险高于原地升级。
- 首版即引入邮箱、手机号、OAuth、MFA 和密码找回：能力更完整，但超出当前“先稳定绑定长期资产”的最小目标，并引入额外外部依赖和合规面。

## Consequences

- 所有长期资产表必须以稳定 `user_id`/账号归属 ID 隔离，客户端本地缓存和待发送队列同样按该 ID 分键。
- 注册/登录接口必须独立限流、限制请求体，并对未知用户名和错误密码返回同一错误。
- 生产迁移 PostgreSQL 时不得重写现有 `user_id`；匿名升级和账号数据须一起迁移与校验。
- 首版没有找回密码、MFA、Passkey 或会话管理；在这些能力实施前必须明确告知用户，不能把简单账号描述为高保证身份认证。
